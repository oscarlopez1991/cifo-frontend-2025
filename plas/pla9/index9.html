1. Spread, rest i destructuring objects

Expliqueu de manera entenedora per què es produeix aquest error...

L'error es produeix perquè la funció chooseBetween(artist1, artist2) espera rebre dos arguments separats, però se li està passant un de sol: l'array artists sencer.

Dins de la funció, el paràmetre artist1 rep l'array complet [{ name: 'Miquel' }, { name: 'David' }], mentre que el paràmetre artist2 queda com a undefined.

Quan el codi intenta accedir a artist1.name o artist2.name, falla. En el primer cas, perquè un array no té la propietat name. En el segon cas, perquè intentar accedir a una propietat de undefined llança un error de tipus (TypeError). La solució és fer servir l'operador spread (...) per "desempaquetar" l'array en arguments individuals: chooseBetween(...artists).

Quin mecanisme s'està aplicant a les dues primeres línies?

El mecanisme que s'està aplicant és l'assignació per desestructuració (destructuring assignment), una característica de JavaScript modern que permet extreure dades d'arrays o objectes d'una manera molt més neta i concisa.

  • A la primera línia, const [a1, a2, a3] = artists;, s'aplica la desestructuració d'arrays. Aquesta sintaxi "desempaqueta" els valors de l'array artists i els assigna a les variables a1, a2 i a3 segons la seva posició. És l'equivalent a fer:
    const a1 = artists[0];
    const a2 = artists[1];
    const a3 = artists[2];
  • A la segona línia, const {name, art} = a2;, s'aplica la desestructuració d'objectes. Aquesta sintaxi extreu les propietats de l'objecte a2 i crea noves variables amb el mateix nom que les propietats. És l'equivalent a fer:
    const name = a2.name;
    const art = a2.art;

2. Emmagatzematge local (local storage)

Expliqueu de manera entenedora quins són els principals avantatges que ofereix l'emmagatzematge local d'informació.

L'emmagatzematge local (local storage) ofereix diversos avantatges clau per al desenvolupament d'aplicacions web modernes:

  • Persistència de dades: La informació guardada al local storage es manté de forma indefinida al navegador de l'usuari, fins i tot si tanca la pestanya, el navegador o reinicia l'ordinador. Les dades només s'esborren si es fa de manera explícita.
  • Millora del rendiment: Accedir a les dades des del local storage és extremadament ràpid, ja que no requereix cap petició a la xarxa. Això permet que les aplicacions carreguin més de pressa i se sentin més àgils, especialment per desar preferències de l'usuari com el tema (clar/fosc) o l'idioma.
  • Funcionalitat offline: Permet que una aplicació web pugui funcionar sense connexió a Internet. Es poden guardar dades essencials localment i, un cop es recuperi la connexió, sincronitzar-les amb el servidor.
  • Reducció de la càrrega del servidor: En guardar informació no crítica al client, es redueix el nombre de peticions al servidor, estalviant amplada de banda i recursos.
  • Major capacitat: Ofereix una capacitat d'emmagatzematge molt més gran (típicament 5-10 MB per domini) en comparació amb les cookies (que només permeten uns 4 KB).

Expliqueu de manera molt detallada què fa el codi de cada una d'aquestes parts.

Part 2.1: Configuració inicial dels botons

  • document.querySelectorAll('.btn').forEach(...): Aquesta línia selecciona tots els botons (elements amb la classe .btn) i itera sobre cadascun. Per a cada botó, estableix el seu color de fons perquè coincideixi amb el seu contingut de text (p. ex., el botó amb text "#800" es torna de color #800).
  • document.querySelector('.buttons').addEventListener(...): Aquesta línia aplica un únic detector d'esdeveniments (event listener) al contenidor pare dels botons (el div amb la classe .buttons). Aquesta tècnica, coneguda com a delegació d'esdeveniments (event delegation), és més eficient que afegir un detector a cada botó individualment. Escolta els clics que "bombollegen" des dels botons fills cap al pare.

Part 2.2: Funció changeBackground

Aquesta funció s'executa cada vegada que es fa clic dins del contenidor .buttons.

  • if (e.target.classList.contains('btn')): Comprova si l'element que ha rebut el clic (e.target) és realment un botó (té la classe .btn). Això evita que el codi s'executi si es fa clic a l'espai buit entre els botons.
  • document.body.style.background = e.target.textContent + '6';: Si s'ha fet clic en un botó, aquesta línia canvia el color de fons de tota la pàgina. Agafa el text del botó (p. ex., "#800") i hi afegeix un '6' al final, creant un color hexadecimal de 4 dígits amb transparència (p. ex., "#8006").
  • saveBackgroundColor();: Crida la funció que s'encarregarà de guardar el nou color de fons a l'emmagatzematge local del navegador.
  • e.preventDefault();: Com que els botons són enllaços (<a href="#">), aquesta línia evita el seu comportament per defecte, que seria fer saltar la pàgina a la part superior.

3. Classes i mòduls

Expliqueu quina és aquesta part i en què es diferencia de la sintaxi que havíem utilitzat fins ara.

La part clau és l'atribut type="module" a l'etiqueta <script>. Aquesta és la sintaxi que habilita l'ús de mòduls natius de JavaScript (ES6).

La diferència principal amb la sintaxi anterior (sense type="module") és com es gestiona l'àmbit (scope) de les variables i funcions:

  • Scripts tradicionals: Les variables declarades en un arxiu són globals, la qual cosa significa que poden xocar amb variables d'altres arxius si tenen el mateix nom.
  • Mòduls: Cada arxiu té el seu propi àmbit privat. Les variables no són accessibles des de fora, tret que s'exportin explícitament amb export i s'importin en un altre arxiu amb import. Això evita conflictes i fa que el codi sigui més organitzat i reutilitzable.

Altres diferències clau:

  • Comportament de càrrega (defer): Aquesta és una diferència fonamental. Els mòduls es comporten com si tinguessin l'atribut defer per defecte. Això significa que el navegador els descarrega en paral·lel mentre continua analitzant l'HTML, i només els executa un cop l'anàlisi de la pàgina ha acabat. En canvi, els scripts tradicionals són bloquejants per defecte: aturen l'anàlisi de l'HTML, descarreguen el script, l'executen i després continuen, la qual cosa és molt pitjor per al rendiment.
  • Mode estricte (Strict Mode): Els mòduls s'executen sempre en mode estricte de JavaScript ('use strict') de manera automàtica. Això ajuda a prevenir errors comuns i promou millors pràctiques de codificació. En els scripts tradicionals, cal activar el mode estricte manualment.

Expliqueu de manera clara quina sintaxi cal seguir per definir una classe i quina sintaxi s'utilitza després per crear un objecte d'aquesta classe.

Una classe és com un plànol o una plantilla per crear objectes. Un objecte és la instància concreta creada a partir d'aquesta plantilla.

Sintaxi per definir una classe (la plantilla):

  • S'utilitza la paraula clau class seguida del nom (p. ex., class Person).
  • A dins, es defineix un mètode especial anomenat constructor, que inicialitza les propietats que tindrà cada objecte (this.name = name;).
  • També es poden definir altres mètodes (funcions) que els objectes podran executar, com ara greet().

Sintaxi per crear un objecte (la instància):

  • S'utilitza la paraula clau new seguida del nom de la classe i els arguments que necessita el seu constructor. Per exemple: const albert = new Person('Albert', ...);.
